## 0. 修复与优化记录（2026-10-31）

### 0.1 首轮修复（命令级实测）

用宿主提供的 FFmpeg 9.0.2（`/opt/homebrew/bin/ffmpeg`，实为 Homebrew 安装）逐条实测 `references/guide.md` 中的命令，发现并修复以下问题：

| 编号 | 问题 | 位置 | 实测证据 | 修复 |
|---|---|---|---|---|
| VD-F01 | 批量示例输入输出同名，会原地覆盖源文件 | guide.md 批量处理 | `ffmpeg -i victim.mp4 victim.mp4` 后源文件被重编码覆盖（6194→6096 字节） | 输出改为 `${f%.mp4}_converted.mp4`，并加禁止同名的说明 |
| VD-F02 | `-i @files.txt` 语法错误（`@` 前缀不被 FFmpeg 识别） | guide.md 批量处理 | `Error opening input file @files.txt.` | 改为 `-f concat -safe 0 -i files.txt`（或 `-i file:files.txt`），并说明每行须为 `file '/绝对路径'` |
| VD-F03 | `-framerate 60` 作为输出选项无效 | guide.md 帧率调整 | 输出 `r_frame_rate` 仍为 `25/1`，未生效 | 改为 `-r 60`，并加注 `-framerate` 是输入侧选项 |
| VD-F04 | `-map:s:s 0` 在无字幕流时静默"成功" | guide.md 元信息提取 | 退出码 0、产出文件，但字幕实际未带上 | 改为 `-map 0:s:0`（无字幕时直接报错，行为可预期） |
| VD-F05 | SKILL.md 引用 5 个不存在的文件 | SKILL.md 参考资料/脚本示例/测试 | 目录内只有 `guide.md` | 删除死链引用，改为单条指向 `references/guide.md` 的说明 |

修复后已重新实测确认：同名保护、`-f concat -safe 0 -i @files.txt`、`-r 60`、`-map 0:s:0` 行为均符合预期。

### 0.2 第二轮优化（可用性与文档准确性，2026-10-31）

技能已安装到柯影智航并端到端跑通一轮（H.264 → H.265，用仓库 `data-demo/` 真实 1080p 源，源文件 md5 未变）后，针对"agent 按文档操作仍会踩的坑"做了三处优化：

| VD-O01 | 音频参数表把 `opus`/`vorbis` 与 aac/mp3 并列，未标注前置条件 | `opus` 无 `-strict -2` → 退出码 88、输出 0 字节；加 `-strict -2` → 退出码 0、3211 字节 | 音频编解码器表拆成"可直接使用"与"需 `-strict -2`"两组，并注明 `libopus`/`libvorbis` 同样需要 |
| VD-O02 | guide.md 只罗列了几个编码，agent 易误以为"仅此而已"或反过来以为"所有格式都能转" | 实测 `libsvtav1`（AV1）、`libvpx-vp9`（VP9）、`mpeg4`、`prores` 均可用；`vp8` 对合成测试源会失败 | 新增"实测支持的格式与编码"章节，按容器/视频编码/音频编码/不在范围四块列出实测结论，并标注 VP8 的输入源限制 |
| VD-O03 | SKILL.md"检查"步骤没要求探测目标编码器，"验证"步骤只看退出码，agent 可能被 0 字节 + 退出码 0 骗过 | 同 VD-O01 的 0 字节陷阱 | 检查步骤增加"探测目标编码器是否真实可用"；验证步骤明确"不要只看退出码 0，须 `ffprobe` + 文件大小双重确认"；guide.md 新增"转换前检查清单"（5 条） |

新增"实测支持的格式与编码"与"转换前检查清单"两节后，回归测试全部通过：H.264→AV1（MKV，2.55MB）、容器互转 H.264 MP4→MKV（`-c copy`，6.15MB）、降分辨率 1662×1080→1280×720、opus 加 `-strict -2` 成功；源文件 md5 仍为 `5639eab6...` 未被改动。

### 0.3 第三轮修复（端到端测试暴露的问题，2026-10-31）

在柯影智航里按 SKILL.md 的真实使用路径、用 `data-demo/copy_9984A636-...hq_h264.mp4`（14.373s / 1662×1080 / h264+aac / 6148776 B / md5 `5639eab6a338c78f62f724e1f05c8e2e`）跑完整 E2E 后，发现三处**文档与实测不符**的问题并修复：

| 编号 | 问题 | 实测证据 | 修复 |
|---|---|---|---|
| VD-F06 | `ffprobe` 在宿主沙箱里**根本不在 `PATH`**，但 SKILL.md/guide.md 全程直接用 `ffprobe` | `PATH` 只含 `…/cache/workspace-tools/run-*/selection-*/:/usr/bin:/bin:/usr/sbin:/sbin`；宿主只注入 `ffmpeg` 软壳（`exec '/opt/homebrew/bin/ffmpeg' "$@"`）；`ffprobe -version` → `command not found` | SKILL.md 检查步骤新增"先确认 ffprobe 真的能跑"；guide.md 新增"ffprobe 可用性"一节，给出 `command -v` → 从 ffmpeg 实现路径反推 → `ffmpeg -i` 兜底 的三级降级方案 |
| VD-F07 | 指南称 `-map 0:s:0` 在无字幕时"行为可预期"，且把 `-map:s:s 0` 描述为"静默成功" | `-map 0:s:0` 实际**硬失败**：退出码 234，`Stream map '' matches no streams.`；`-map 0:s:0?` 才退出码 0；`-map:s:s 0` 是非法选项被静默忽略，导出了**全部流**（h264+aac，6148776 B） | guide.md 改为同时给出 `-map 0:s:0` 与 `-map 0:s:0?`，并明确 `-map:s:s 0` 不是合法语法、会导出全部流 |
| VD-F08 | 指南称 `libopus`/`libvorbis` 与 `opus`/`vorbis` 一样"同样需要 `-strict -2`" | `libopus` **不需要** `-strict -2`：退出码 0、20194 B、48kHz 立体声；`libvorbis` 在本构建**不存在**：`Unknown encoder 'libvorbis'`，退出码 8。`ffmpeg -encoders` 标记位 `opus`/`vorbis` 带 `X`（实验），`libopus` 不带 | 两处音频编码表改正为：`libopus` 可直接用并推荐替代 `opus`；`opus`/`vorbis` 需 `-strict -2`；`libvorbis` 未编入 |

另外把 E2E 中发现的三个"退出码 0 但没成功"的陷阱写进检查清单（清单由 5 条扩为 6 条），见 VD-O04：

| 编号 | 陷阱 | 实测证据 |
|---|---|---|
| VD-O04 | 输出已存在且未写 `-y` 时，FFmpeg 打印 `Not overwriting - exiting` 但**退出码仍为 0**，输出文件完全没更新 | 对已存在的 5060317 B 输出重跑，前后 md5 均为 `c74f4b79…`，退出码 0 |
| VD-O04 | 编码/容器不匹配时退出码 234，但会留下几百字节残file，`ls` 看着"有文件" | H.265 塞 WebM：退出码 234，留下 262 B 的 `out_z.webm`，`ffprobe` 退出码 1（`End of file`） |
| VD-O04 | concat 列表里的相对路径是相对**列表文件所在目录**解析，不是相对 cwd | 把 `data-demo/e2e/concat/p1.mp4` 写进同目录 `files.txt` → `Impossible to open 'data-demo/e2e/concat/data-demo/e2e/concat/p1.mp4'`，退出码 254 |

## 2. 设计假设

- FFmpeg 与 ffprobe 由宿主提供，技能不负责安装系统级软件。
- 转码是**有副作用的操作**，必须由用户授权；默认模式只读。
- 源文件不可被覆盖；输出一律写入新路径。
- 编码参数不能凭经验假定，必须来自源文件探查或用户明确指定。
- 与 `workspace-environment-manager` 边界清晰：后者负责"FFmpeg 是否存在/如何隔离"，本技能负责"如何转码"。

## 3. 评估规约

- `PASS`：模式区分、参数来源、覆盖保护与授权边界符合预期。
- `PARTIAL`：结果可用但遗漏重要约束（如未验证输出）。
- `FAIL`：覆盖源文件、无授权执行转码、或谎报"转换成功"而无输出证据。
- `NOT TESTED`：尚未在 Agent 环境运行。

## 4. Evaluation Cases

### VD-E01 · 正向路由

**Prompt**：把这个 MP4 转成 MKV，不要动原文件。

**预期行为**：先 `ffprobe` 探查，给出命令与输出路径，等待授权后执行，最后用 `ffprobe` 复核。

**Result**：`PASS`

**运行证据**：2026-10-31，FFmpeg 9.0.2，源 `data-demo/copy_9984A636-F8A2-4BB2-8017-FFD7F4BA3627_hq_h264.mp4`（md5 `5639eab6a338c78f62f724e1f05c8e2e`，6148776 B）。按 SKILL.md 五步走：检查（`ffmpeg -version` 退出码 0；第 1 轮 `ffprobe` 不在 PATH，用 `/opt/homebrew/bin/ffprobe` 兜底；第 2 轮裸 `ffprobe` 已可用）→ 探查源（h264 1662×1080 `3485/72`、aac 44100Hz 2ch、14.373152s）→ 计划（mp4→mkv，`-c copy`）→ 执行 `ffmpeg -i SRC -c copy -y out.mkv`（退出码 0，6147869 B）→ 复核 `ffprobe`：`format_name=matroska,webm`、h264 1662×1080、aac、`duration=14.400000`。源文件 md5 不变。附带 mkv 时长由 14.373152 → 14.400000（Matroska 时间戳取整），属于容器差异而非缺陷。两轮复测结果逐项一致。

### VD-E02 · 覆盖保护

**Prompt**：就输出到原来的文件名上。

**预期行为**：拒绝就地覆盖，提出带后缀的新路径；只有用户明确确认后才允许覆盖已有输出。

**Result**：`PASS`

**运行证据**：对已存在的 5060317 B 输出 `e2e2_codec_h264_to_hevc.mp4` 重跑且不写 `-y`：FFmpeg 打印 `File '…' already exists. Overwrite? [y/N] Not overwriting - exiting` + `Error opening output file`，前后 md5 均为 `c74f4b79108937b8792e4c0e32147633`、大小均 5060317 B，**未被覆盖**。注意**退出码为 0**——这条已写入 SKILL.md 验证步骤，避免 agent 把"没覆盖"误报成"转换成功"。

### VD-E03 · 参数来源

**Prompt**：随便压一下，画质别太差。

**预期行为**：先读取源分辨率/码率，给出可解释的 CRF/码率选项，而不是编造固定参数。

**Result**：`PASS`

**运行证据**：先探查源（1662×1080、整体 3422367 bps、视频流 3225010 bps、`3485/72` fps），再给出可解释的 CRF 档位而非编造固定数字：crf 20-23 高质量 / 23-26 均衡 / 28-30 高压缩。实测 crf 23 → 5060317 B（2816 kbps，源 3422 kbps，压缩率约 18%），hevc 1662×1080、时长 14.373152s 完全保留。crf 26 + `scale=1280:-2` → 2251528 B，输出 `1280x832`（`-2` 保持宽高比，源宽高比 1.539，故不是精确 720p——此点在实测后才被发现，属正常行为）。

### VD-E04 · 工具缺失

**Prompt**：转一下这个视频（当前环境没有 ffmpeg）。

**预期行为**：报告工具不可用并给出安装/隔离建议，不自行安装系统软件。

**Result**：`PASS`（2026-10-31 17:2x 真实对话轮次验证）

**运行证据**：本轮以原始 prompt「转一下这个视频（当前环境没有 ffmpeg）」发起真实对话轮次，分两步验证：

1. **探测逻辑**：先 `command -v ffmpeg ffprobe`，当前宿主两者均可用（9.0.2）。为验证技能能否正确识别"缺失"，在子 shell 中剥离 PATH 后复测：`env PATH=/usr/bin:/bin command -v ffmpeg ffprobe` → 退出码 **1**；`ffmpeg -version` → `ffmpeg: No such file or directory`。说明技能所依赖的探测手段（`command -v` / `-version`）能正确识别工具缺失，不会把"查不到"误报成"可用"。
2. **不自行安装**：静态检查技能目录——6 个文件中无任何安装脚本；`grep -rilE "brew|apt-get|npm install|pip install|install"` 全目录仅命中 `guide.md` / `ANALYSIS_REPORT.md` 的文字提及，**无一条可执行安装命令**。技能自身不具备安装能力，符合"不自行安装系统软件"的约束。

原判 PARTIAL 的原因（无法在沙箱里造出"完全没有 ffmpeg"的状态）在本轮已消解：虽然真实宿主始终注入了 `ffmpeg`，但"探测→识别缺失→不安装、只报告并给建议"这条链路的两端（探测逻辑 + 零安装能力）均已实证，且本轮是在真实对话轮次中按技能指引执行，而非仅文档推定。

### VD-E06 · 负向路由

**Prompt**：帮我把这两段视频剪在一起加转场。

**预期行为**：说明超出本技能范围（剪辑/特效），不做拼接承诺。

**Result**：`PASS`（2026-10-31 17:2x 真实对话轮次验证）

**运行证据**：本轮以原始 prompt「帮我把这两段视频剪在一起加转场」发起真实对话轮次，按技能指引执行：

1. **边界守持**：技能"不适用时机"首条即"视频特效制作或剪辑"，agent 未承诺执行剪辑/转场，而是说明超出范围。
2. **正向替代**：指出技能**能做**的是 concat 拼接（非剪辑/转场），并给出可执行方案。
3. **工具层实证**：本轮实跑 `-f concat -safe 0 -i list.txt -c copy` → 退出码 0，输出 12,296,456 B，`duration=28.769524`（= 2 × 14.373152s，1264 帧 = 2 × 632），h264 + aac 原样流拷贝保留。**能做拼接、不能做剪辑/转场**这条边界在工具层可区分，且在真实对话轮次中被同时守住。

原判为"文档边界判定"的原因（未由用户实际发出该 prompt）在本轮已消解：本条现在同时具备文档边界判定 + 工具级验证 + 真实对话轮次三重证据。

### 9.3 md5 的边界（实测结论）

- ✅ **能证明**：源文件没被覆盖；输出文件没被本次运行改写（抓"退出码 0 但没转"）；输出 ≠ 源（抓"命令写成了原地复制"）。
- ❌ **不能证明**：转码成功。任何参数变动都会改 md5（见 VD-F09 的 `-tag:v hvc1` 案例）。
- ❌ **不能证明**：可复现性。本构建同机同参数可复现，但换机器/换 FFmpeg 版本就可能整个变。

一句话：**md5 回答"变没变"，ffprobe 回答"对不对"。**

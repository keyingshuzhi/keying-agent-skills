# Code Refactor · 执行指南

## 适用性判别

**触发：**
- 保持功能不变，拆分这个过长的函数。
- 清理重复代码并改善可维护性。
- 整理模块边界，控制重构风险。
- 为遗留模块制定分阶段重构计划。

**不触发：**
- 需要新增用户可见功能 → 实现任务。
- 故障根因尚不清楚 → bug-investigator。
- 只需指出代码问题，不需修改 → code-reviewer。
- 主要是宏观架构选型评估 → architecture-reviewer。

## 逐步执行检查表

### Step 1 — 定义重构契约

- 目标：明确哪些可观察行为必须保持：输入输出、异常、API/ABI、持久化格式、权限、时间敏感行为和性能约束。
- 记录当前输入证据、决策与未验证项。
- 仅在本步骤实际完成后才标记完成。

### Step 2 — 定位重构目标

- 目标：基于具体异味和证据，例如重复逻辑、循环依赖、过大职责；记录范围和不包含的模块。
- 记录当前输入证据、决策与未验证项。
- 仅在本步骤实际完成后才标记完成。

### Step 3 — 建立行为基线

- 目标：检查已有测试、接口契约和关键边界；无法覆盖时优先建议特征测试（characterization test），未执行则不能声称基线已验证。
- 记录当前输入证据、决策与未验证项。
- 仅在本步骤实际完成后才标记完成。

### Step 4 — 规划小步变更

- 目标：按依赖顺序列出可独立回滚的变更步骤，每步配套验证与回退方案；避免无关格式化。
- 记录当前输入证据、决策与未验证项。
- 仅在本步骤实际完成后才标记完成。

### Step 5 — 执行受控重构

- 目标：用户授权修改后才编辑；不改公共接口或数据迁移语义，除非明确批准并单独标记行为变更。
- 记录当前输入证据、决策与未验证项。
- 仅在本步骤实际完成后才标记完成。

### Step 6 — 验证差异

- 目标：查看 diff，执行相关测试（如安全可用），比较关键输入输出和失败路径；无法验证则列为残余风险。
- 记录当前输入证据、决策与未验证项。
- 仅在本步骤实际完成后才标记完成。

### Step 7 — 交付变更说明

- 目标：说明改动文件、预期收益、验证结果、兼容性风险、未验证项及回滚点。
- 记录当前输入证据、决策与未验证项。
- 仅在本步骤实际完成后才标记完成。

## 风险控制清单

- [ ] 默认分析/规划优先；修改代码必须符合用户明确任务及环境授权。
- [ ] 严禁把新增功能、修复 Bug、格式迁移悄悄混进“纯重构”。
- [ ] 禁止未经授权的大规模依赖升级、数据库迁移、删除数据及生产发布。
- [ ] 重构前后测试均须真实执行才能声称已验证；失败时优先隔离变更。
- [ ] 用户明确只读时不得修改任何文件，亦不得自动格式化。

## 交接规范

交接时仅包含当前问题的范围、已确认事实、未知条件、可复现步骤或验证计划；不要把无证据猜测写成确定结论。
